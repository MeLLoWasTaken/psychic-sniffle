# Decisions

Every choice not specified in docs/DESIGN.md, newest first. One line of reasoning each. Choices that are expensive to reverse need the human's approval, noted in the entry.

| Date | Decision | Reason | Approved by |
| --- | --- | --- | --- |
| 2026-09-29 | Gallows Courtyard is a 39 by 36 m courtyard with the two starting rooms (8 by 4.5 m) outside it, behind 8 m gates; pillars at (±8, ±7); map bounds 50 m square | The first layout had full-width gates that left two 40 m strips behind them, where kiting healers got cornered, and was not a room. A 29 m wide version favored melee 75/25; the 39 m courtyard with the Oracle fix below tests 55/45 | Model |
| 2026-09-29 | Arenas are built at load time from their map data by `MapBuilder`, not hand-placed in scenes; colliders carry a tag the art kit uses to pick pieces | Visuals and collision can never drift from the server's movement and line-of-sight data; a test compares scene collision with server line of sight | Model |
| 2026-09-29 | Physics layers: 1 `world` (anything solid), 2 `los_blocker` (blocks line of sight) | The design asks for line-of-sight blockers on their own collision layer; the camera and spell effects will query them | Model |
| 2026-09-29 | Lighting presets are data (`data/lighting/<id>.json`), validated by schema, named by each map | One place to tune a map's look; the same numbers can drive Blender previews | Model |
| 2026-09-29 | Movement and gate unit tests use a fixed test map (`test/fixtures/fixture_map.gd`); real maps have their own tests | Map layout changes broke unrelated movement tests | Model |
| 2026-09-29 | The Oracle bot casts its fast heal below 65% and its group heal below 80% (was 40% and 70%) | Under melee pressure it could not cast its big heal and had nothing to do between 40% and 75% health, which decided most matches | Model |
| 2026-09-29 | Units act in a seeded shuffled order each tick (`Sim.turn_order`, from the match seed and tick number), for combat resolution, server input processing and bots; bots all decide from the same start-of-tick world | Fixed id order made the team created first win same-tick races: a mirror match-up went 42 to 11. After the change: 19-16 and 17-18 | Model |
| 2026-09-29 | Rage comes from auto-attacks (10 per 1,000 damage) and damage taken (6 per 1,000); abilities grant only their own fixed rage | At 8 rage per 1,000 of any damage dealt, Wide Hew refunded more than its cost and the Warblade could use it every global cooldown | Model |
| 2026-09-29 | The server keeps every unapplied input sorted by sequence number and waits for a missing one until 4 newer inputs are queued, then counts it lost | It used to drop older inputs that arrived after newer ones, losing a tick of movement when packets were reordered | Model |
| 2026-09-29 | Snapshots carry the last tick an ability moved the player's own unit (charge, blink, knockback); protocol version 3 | The client treats that correction as server-caused, like a new stun, rather than a prediction error | Model |
| 2026-09-29 | Bots dispel enemy buffs only when they are marked major (offensive or defensive cooldowns) | Dispelling a cheap heal-over-time every global cooldown locked an Arcanist and an Oracle into doing nothing else for minutes | Model |
| 2026-09-29 | Prediction corrections that arrive together with an unforeseeable change to the player's own movement effects (a stun, root, slow or fear applied, refreshed, or ended early by damage, a dispel or Break Free) or with an ability moving the player (charge, blink, knockback) are counted separately from prediction errors; the 0.5 m / 0.1 m limits apply to the rest | No client can know about a server-applied stun until the snapshot arrives, so these corrections are not prediction errors. Effects that expire on schedule and fear movement are predicted and still count. In 150 ms test matches with combat: 0 counted corrections, 2-4 effect corrections per bot up to 1.5 m. Visual smoothing of those is follow-up F-03 | Model |
| 2026-09-29 | Bots read a "view" dictionary with the same shape whether built by the server-side `MatchRunner` (batch simulation) or by a network client from snapshots | One bot brain serves balance simulations and networked test matches; balance results transfer to real matches | Model |
| 2026-09-29 | Bot behaviour lives in `data/bots/<spec>.json` (targeting, ranges, priority rules with conditions); bots skip crowd control into diminishing returns of 2 or more | All gameplay content is data; the DR rule stopped an Arcanist bot from spending whole matches casting freezes into immunity | Model |
| 2026-09-29 | Impact sounds contain no sustained pure tones above 200 Hz; metal is made from resonant noise that fades within about 0.1 s | Human feedback: a tonal impact read as scoring a point; enforced by `tests/test_audio.py` | Human feedback |
| 2026-09-29 | Heals and other big positive effects carry a low-end body and a soft impact, not only a high shimmer | Human feedback: the high ring alone felt light | Human feedback |
| 2026-09-29 | The compiled Godot binary is committed as two xz parts (67 MB total) in `tools/env/bin/`, with a SHA-256 check on restore | Git LFS uploads go to a storage host the cloud workspace blocks; plain git files must stay under GitHub's 100 MB limit (parts are kept under the 50 MB warning size); recompiling costs about an hour per fresh workspace | Model |
| 2026-09-29 | ENet's packet throttle is pinned open on every peer | It silently dropped up to 17% of snapshots when round trip rose under CPU load; the game controls its own send rate and bandwidth | Model |
| 2026-09-29 | The latency check compares measured round trip with the simulated lag plus a 10 ms local base (the round trip with no simulated lag, from polling at up to 240 frames per second) | The simulator adds exactly its setting; the original check compared total round trip and would have failed a correct simulator. This clarifies what is measured and does not loosen the 10% tolerance | Model |
| 2026-09-29 | Simulated jitter is a bounded random walk, not an independent random delay per packet | Independent per-packet jitter reordered about 6% of 60 Hz snapshots, which real network queueing rarely does | Model |
| 2026-09-29 | The server applies every client input exactly once and in order: it waits when no input has arrived and applies two per tick when more than 6 are queued; it never drops or repeats inputs | Dropping and repeating inputs caused prediction errors up to 0.93 m and lost one-shot actions (targeting) under 150 ms lag; exactly-once gave 0 corrections | Model |
| 2026-09-29 | Movement, collision and line of sight are pure math on map colliders (circles and boxes), not the physics engine | Server, client prediction and tests must produce identical results; engine physics is harder to keep deterministic across processes | Model |
| 2026-09-29 | Networking uses Godot's low-level ENet API with a hand-written binary protocol, not high-level RPCs | Full control of channels, packet contents and size; inputs carry the last 3 inputs for loss resistance | Model |
| 2026-09-29 | Screenshots use Forward+ on Mesa lavapipe (software Vulkan) under Xvfb via `tools/screenshot.sh`; 60 frames at 1920×1080 take about 70 s | Forward+ works without a GPU, so screenshots match the real renderer; no Compatibility-renderer fallback needed | Model |
| 2026-09-28 | Sound source: effects are synthesized by `tools/audio/synth.py` by default; CC0 sample libraries are allowed for sounds synthesis handles poorly (voices, footsteps on varied surfaces, cloth) | Synthesis is reproducible and editable as text, fits the loop, and has no licensing risk; the model reviews spectrograms because it cannot listen, so the human should spot-check by ear at each milestone gate | Model; human to confirm by ear |
| 2026-09-28 | Sound files are Ogg Vorbis, 48 kHz mono; the generator measures the encoded peak and corrects it | Vorbis encoding raised peaks by up to 1.3 dB, which could break the "nothing louder than the CC warning" rule | Model |
| 2026-09-28 | Stylized materials keep metallic at or below 0.3; metal is painted dark with bright worn edges | Higher metallic values mirror the brown ground and warm key light, so iron read as wood in the test crate | Model |
| 2026-09-28 | Until the texture bake (M1-17), exports carry flat base colors | glTF cannot store procedural shader networks; they exported as white | Model |
| 2026-09-28 | Starting resource values: mana 50,000 (400/s), rage 100 (decays 2/s out of combat), energy 100 (10/s), combo points 5, focus 100 (5/s), runes 6 (10 s recharge), runic power 100, fury 100, essence 5 (5 s recharge) | The design names the resources but not their numbers; these are tuning placeholders for balance simulations to adjust | Model |
| 2026-09-28 | Jump: 8 m/s up with 20 m/s² gravity (about 1.6 m jump height); backpedal at 60% speed; auto-attack 1,200 damage every 2.0 s | Not specified in the design; values give classic MMO movement feel | Model |
| 2026-09-28 | Draft content (`status: draft`) gets structural checks only; the kit template and talent point totals apply once marked `complete` | Lets data grow incrementally without failing validation, while still enforcing the design rules on finished specs | Model |
| 2026-09-28 | Blender runs as the `bpy` 4.5.4 Python module (Blender 4.5 LTS) in the cloud workspace | download.blender.org is blocked; PyPI is allowed; 4.5 is the current long-term-support line | Model |
| 2026-09-28 | Godot is compiled from the `4.7.2-stable` source tag | GitHub release binaries are blocked in the cloud workspace; `git clone` is allowed | Model |
| 2026-09-28 | Server tick rate 60 Hz with 60 Hz delta-compressed snapshots; tick budget under 8 ms; client bandwidth under 96 KB/s | Requested by the human (up from 30 Hz) | Human |
| 2026-09-28 | Engine: Godot 4.7 | Only engine of the three that a model can build, run, test and screenshot from text files on headless Linux; renderer covers the stylized art direction | Human deferred to the model's judgment |
